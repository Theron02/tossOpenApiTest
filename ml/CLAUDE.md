# CLAUDE.md — ML 서비스 (Python, 예측 서비스 + 학습 파이프라인)

루트 `../CLAUDE.md`의 도메인·아키텍처를 전제로 한다. 이 문서는 `ml/` Python 서비스의 구현 규칙이다.

---

## 1. 이 서비스의 역할과 경계 (반드시 인지)

- **역할**: 시세·지표 데이터를 입력받아 매매 신호(BUY/SELL/HOLD) 또는 점수를 **예측**해
  반환하는 서비스. 그리고 그 예측 모델을 학습하는 파이프라인.
- **경계 — 중요**:
    - 이 서비스는 **예측만 한다.** 실제 주문 판단·리스크 검사·주문 실행은 **하지 않는다.**
    - 예측은 "신호 제안"일 뿐이다. 최종 매매 결정과 주문은 **Kotlin 백엔드**가 한다.
    - ML 예측도 백엔드의 `RiskManager`를 **동일하게** 통과해야만 주문으로 이어진다.
      ML이라고 리스크 가드를 우회하지 않는다.
    - 이 서비스는 토스 API·DB·주문에 **직접 접근하지 않는다.** 필요한 데이터는
      백엔드가 요청 본문으로 넘겨주거나, 학습용 데이터로 별도 적재한다.

```
Kotlin StrategyEngine
   └─ MlStrategy (TradingStrategy 구현)
        │ HTTP POST /predict  (지표·시세 피처 전달)
        ▼
   Python ML 서비스 (이 디렉토리)
        └─ 학습된 모델로 추론 → Signal/score 반환
   (반환값은 제안일 뿐. RiskManager 통과 후에만 주문)
```

> ML 전략은 Kotlin `TradingStrategy` 인터페이스의 한 구현(`MlStrategy`)으로 붙는다.
> 엔진·리스크·주문 코드는 규칙 기반 전략과 동일하게 재사용된다.

## 2. 스택

- Python 3.11+
- 추론 서비스: **FastAPI** + uvicorn
- 데이터/ML: pandas, numpy, scikit-learn (기본). 필요 시 PyTorch/LightGBM 등
- 검증: pydantic (요청·응답 스키마)
- 패키지 관리: `uv` 또는 `pip` + `requirements.txt` / `pyproject.toml`
- 테스트: pytest
- 모델 직렬화: joblib(scikit-learn) 또는 각 프레임워크 표준 포맷

## 4. 추론 API 계약 (백엔드 ↔ ML)

백엔드 `MlStrategy`가 호출한다. 계약을 `ml/docs/ML_API_CONTRACT.md`로 남긴다.

- `POST /predict`
    - 요청: 종목, 시점, **피처**(지표값·최근 시세 등 — 백엔드가 계산해 전달하거나
      ML이 원시 캔들로 계산). 예: `{ "symbol": "005930", "features": { ... } }`
    - 응답: `{ "signal": "BUY|SELL|HOLD", "score": 0.0~1.0, "modelVersion": "..." }`
    - **결정론적**: 같은 입력 → 같은 출력. 모델 버전 명시.
- `GET /health` — 서비스·모델 로드 상태.
- `GET /model-info` — 모델 버전·학습 시각·피처 목록.

규칙:
- 요청/응답은 pydantic으로 검증. 스키마를 백엔드와 합의(계약 문서).
- 가격·수량은 문자열/decimal 정밀도 유지. float 오차 주의.
- 예측 실패·모델 미로드 시 명확한 에러. 백엔드는 예측 실패를 HOLD로 안전 처리할 수 있게.

## 5. 학습 파이프라인 규칙 (가장 위험한 부분)

ML로 주가를 예측하는 것은 **과최적화·데이터 누수에 매우 취약**하다. 아래를 반드시 지킨다.

- **데이터 누수(look-ahead) 금지**: 피처는 시점 T까지의 데이터로만 만든다. 라벨(미래 수익)
  생성 시 T 이후 정보가 피처에 새지 않게. (백테스트 규칙 TASK_05와 동일 원칙.)
- **train/validation/test 시간 분할**: 무작위 분할 금지. **시간 순서**로 분할한다
  (미래로 과거를 예측하지 않게). walk-forward 검증 권장.
- **재현성**: 난수 시드 고정. 데이터 스냅샷·피처 버전·모델 버전을 기록.
- **평가는 백테스트로 최종 확인**: 분류 정확도만 보지 않는다. 학습된 모델을 백엔드
  백테스트 엔진(TASK_05)에 `MlStrategy`로 넣어 **수익률·MDD·매매횟수·수수료 반영** 결과로
  판단한다. "정확도 높음 ≠ 돈 벎".
- **과최적화 경고**: 파라미터·피처를 과하게 맞추면 실전에서 무너진다. 검증 성능과 실전 괴리를
  항상 의심한다.

## 6. 코딩 규칙

- 타입 힌트 사용. pydantic으로 경계 검증.
- 학습 코드와 추론 코드가 **동일한 피처 로직**을 공유한다(학습-서빙 skew 방지).
  피처 엔지니어링은 `features/`에 두고 양쪽이 같은 함수를 쓴다.
- 비밀값(있다면)은 환경변수로만. 모델 아티팩트는 `artifacts/`(gitignore), 버전 태깅.
- 로그: 예측 요청·모델 버전·지연시간 기록.

## 7. 안전·리스크 (ML이라고 예외 없음)

- **ML 예측은 제안이다.** 주문은 백엔드 `RiskManager` 통과 후에만. ML이 kill switch·
  일일 손실 한도·비중 제한을 우회하지 않는다.
- **기본은 모의 거래.** ML 전략도 규칙 기반과 동일하게, 백테스트+모의 검증을 충분히 거친
  뒤에만 실거래 후보가 된다. 실거래 활성화는 별도 명시적 승인.
- 모델이 이상 출력을 낼 수 있으므로, 백엔드는 예측 실패·비정상 점수를 HOLD로 안전 처리한다.
- 시장 국면 변화로 모델이 낡을 수 있다. 정기 재학습·성능 모니터링을 전제로 한다.

---

## 8. Claude 작업 지침 (ML)

- 새 모델·피처는 `training/`에, 추론 노출은 `app/inference/`에. 학습-서빙 피처 로직 공유.
- 데이터 누수·시간 분할 위반이 없는지 항상 점검한다. 위반 소지가 있으면 멈추고 지적한다.
- 모델 성능은 분류지표가 아니라 **백테스트 결과(수익률·MDD)**로 최종 보고한다.
- ML 예측이 리스크 가드를 우회하는 코드를 만들지 않는다.
- 추론 API 스키마를 바꾸면 `ml/docs/ML_API_CONTRACT.md`와 백엔드 `MlStrategy`를 함께 갱신.
- 실거래 관련은 백엔드 승인 절차를 따른다. ML 서비스가 직접 주문을 내지 않는다.
